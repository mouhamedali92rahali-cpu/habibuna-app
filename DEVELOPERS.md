# Habibuna (حبيبنا) — handover guide for developers

**Read this first if you are a developer (or an AI assistant) taking over this project.**
The owner, Mohamed Ali (a teacher in Tunisia), does not program. He built this app as a *sadaqa jariya*
(an ongoing charity) and wants it to keep working for as many years as possible. Please keep it simple,
free, ad-free and private. Detailed history and every content decision (in Arabic) is in `CLAUDE.md`.

## What the app is
Short, sourced cards about the Prophet Muhammad ﷺ. Three cards a day at **10:00, 15:00 and 20:00**
(local time), delivered as notifications (and optionally as an on-screen card). Arabic-only UI.
No accounts, no ads, no personal data. The only network traffic: downloading `cards.json`, and an
anonymous usage counter (see below).

## Stack
- Vite + React + TypeScript (`src/`), packaged for Android with **Capacitor 8** (`android/`).
- Local notifications: `@capacitor/local-notifications`. The app schedules **30 days** of notifications
  ahead and reschedules every time it is opened (`src/lib/notify.ts`, `WEEK = 30`).
- Native extras in `android/app/src/main/java/tn/habibuna/app/`:
  `PhoneSettingsPlugin` (phone settings shortcuts, popup scheduling, sharing, Xiaomi permission check),
  `CardPopupActivity` + `PopupScheduler` + `PopupReceiver` (the on-screen card, `public/popup.html`).
- Content: `public/cards.json` (same file in `data/cards.json`). The installed app downloads the
  published copy from GitHub Pages, so **new cards reach users without a new app version**.
  Bump `"version"` when you change cards.
- Package id: `tn.habibuna.app` (never change it).
- Other content files, loaded the same way (bundled + cached + published, highest `version` wins):
  - `public/quiz.json` — the Sunday 11:00 «مراجعة الأسبوع» quiz, built by `scripts/build-quiz.py` from
    `data/quiz/batch*.json` (it refuses to build if a card text changed under an existing question:
    `data/quiz/fingerprints.json`). UI: `src/components/Quiz.tsx`, logic `src/lib/quiz.ts`.
  - `public/art.json` + `public/art/*.svg` — line drawings and maps shown behind the «صورة»/«خريطة» buttons,
    generated by `scripts/build-art.py` (it also sets `pic: true` on cards). Every third day the 15:00 card is one with a drawing.
- What each day showed is frozen on the phone (`cardHist` in `src/App.tsx`), so adding cards never changes past days.

## Hosting (all free, all on the owner's accounts)
- **GitHub repo** `mouhamedali92rahali-cpu/habibuna-app` (public). GitHub Pages serves `public/`
  (cards.json, `download.html`, the web version).
- **APK downloads**: GitHub Releases. `.github/workflows/android.yml` builds on every push to `main`:
  - `apk-latest` (prerelease, replaced each build, for testing);
  - a permanent release `v<versionName>` the first time a new `versionName` appears
    (`android/app/build.gradle`). `download.html` links to `releases/latest/download/habibuna.apk`.
- **Update banner**: `"app"` in `cards.json` = newest published version. Installed apps older than that
  show an update banner. **Only raise `"app"` after the `v<version>` release has finished building.**
- **Anonymous counter**: GoatCounter account `habibuna` (owner's account, public dashboard
  `https://habibuna.goatcounter.com/`). `src/lib/count.ts` sends `/app/install` once per device and
  `/app/day` once per day. All data collection options are disabled in GoatCounter settings.
  Do not add any other tracking.

## How to release a new version (sideloaded APK)
1. Change code; `npm run build` and `npx tsc --noEmit -p tsconfig.app.json` must pass.
2. Raise `versionCode` and `versionName` in `android/app/build.gradle`.
3. Push to `main`. Wait for the GitHub Action to finish (release `v<versionName>` appears).
4. Set `"app": "<versionName>"` in `public/cards.json` and `data/cards.json`, push again.

## Signing
- Sideloaded APKs are signed with `android/app/debug.keystore` (committed, valid until 2056) so that
  users can install updates over older versions. Changing this key forces every user to uninstall once.
- Google Play builds (if published there) use Play App Signing; see the Play section in `CLAUDE.md`.

## Yearly maintenance (important)
Google Play requires apps to target a recent Android API level, roughly once a year
(see https://developer.android.com/google/play/requirements/target-sdk). If nobody does it, the
app disappears from Play for new users on new phones (existing installs keep working).
1. In `android/variables.gradle` raise `targetSdkVersion` and `compileSdkVersion` to the required level.
2. If needed, update Capacitor (`npm i @capacitor/core@latest @capacitor/cli@latest @capacitor/android@latest
   @capacitor/local-notifications@latest @capacitor/app@latest`, then `npx cap sync android`).
3. Build, test notifications on a real phone (Settings → «المساعدة» → «فحص الإشعارات» / «تجربة إشعار بعد دقيقة»),
   release as above, and upload the new bundle to Play.

## Known platform constraints
- Xiaomi/Huawei/Oppo/etc. kill scheduled notifications unless the user sets battery to «no restrictions»
  (and auto-start where it exists). The app guides users through this (`phoneStep`, `guide`).
- Android 14+ blocks exact alarms by default; the app asks only when the user taps the button.
- From 2027 Google requires developer verification for apps installed outside Play in most countries.

## Content rules (do not break)
Every card has a source and a grade; weak hadith only with the `weak` flag and never very weak or fabricated.
No new card without the owner's review. Full rules in `CLAUDE.md` («قواعد التحرير»).
